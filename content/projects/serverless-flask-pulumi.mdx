## Context

A small Flask app that runs on AWS Lambda behind an API Gateway HTTP API. One Pulumi stack, written with the Python SDK, creates every resource. I wrote it up as a tutorial on Medium in July 2025.

## Problem

I wanted to try Pulumi, an infrastructure-as-code tool where you write infrastructure in a normal programming language. A small serverless Flask app was the test.

## What I built

A Pulumi stack with:

- An S3 bucket holding a text file.
- An ECR repository.
- A Lambda function that runs as a container image, built with awsx.
- An IAM role with the `AWSLambdaBasicExecutionRole` policy.
- An API Gateway v2 HTTP API with an `AWS_PROXY` integration, a catch-all route and a `$default` stage.

The Flask app is wrapped with aws-wsgi so Lambda can call it.

## How it works

1. A request reaches the HTTP API.
2. The catch-all route passes it to the Lambda function through the `AWS_PROXY` integration.
3. aws-wsgi hands the request to Flask.
4. Flask returns the contents of `text.txt`.

That file is copied into the container image. The S3 bucket holds a copy, but the app does not read from it.

## What broke and how I fixed it

The article lists three problems and the fix for each.

- The Docker build fails. Run Docker Desktop as Administrator, and share the project directory under Settings > Resources > File Sharing.
- API Gateway returns 500 errors. Set `payload_format_version="1.0"` on the integration.
- Permission errors. Check the IAM roles and the Lambda permissions.
